# 学习协作约定

从第二天开始采用“我讲解和生成代码，你亲自在 PyCharm 中输入”的方式。

## 每段代码的流程

1. 我先说明本段代码解决什么问题、放在哪个文件、依赖哪些已有函数。
2. 我提供带适量中文注释的完整代码，控制在一次容易输入和理解的长度。
3. 你在指定文件中亲自输入并运行。
4. 你把终端结果或错误信息发给我；不要发送 `.env`、API Key 或密码。
5. 我检查运行结果、解释错误，再进入下一段。

除非你明确要求我直接修改，第二天起我不代写 `src`、`scripts` 和 `tests` 中的学习代码。配置文件、复盘文档和只读检查可以由我处理。

## 中文注释标准

- 注释解释“为什么这样做”和关键边界，不逐行翻译 Python 语法。
- 函数使用中文 docstring 说明输入、输出和异常。
- 对页码转换、文件哈希、Milvus 字段和重试上限等易错点写注释。
- 变量和函数名继续使用清晰的英文，便于符合真实项目习惯。

## 每日复盘必须包含

- 当天目标与实际完成情况。
- 新建或修改的文件。
- 每个文件负责什么。
- 文件之间的 `import`、函数调用和数据流关系。
- 核心代码分段解释。
- 实际运行命令与结果。
- 当天遇到的错误及解决方法。
- 面试可能追问的问题。
- 第二天开始前需要掌握的内容。

## Git 工作方式

- 第二天开始创建 GitHub 远程仓库并使用 HTTPS 推送。
- 每天完成并验证后再提交一次，提交信息说明当天成果。
- `.env`、虚拟环境、缓存和 PDF 检查图片不得提交。
- 默认先由你查看 `git diff` 和 `git status`，理解改动后再提交。
